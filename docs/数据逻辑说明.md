## 1. 数据链路总览

```
官网 Web6（222.175.25.10:8006）
│
├─ 实时接口   EnterPriseRealTimeData.ashx   → 当前浓度/流量/状态
├─ 历史接口   HistoryReport.ashx?index=…    → 分钟/小时/日/月（index=2「日」须传裸日期 yyyy-MM-dd）
└─ 导出       历史数据_*.xls（分钟/小时/日三种粒度）
        │
        ▼
GZApiClient / GZMultiAccountClient   （登录、Session、参数拼装）
        │
        ▼
data_processor.py / param_units.py    （单位换算、排放量、状态分类、预测）
        │
        ├─→ 实时监控页（浓度 / 排放量 / 折算 / 状态）
        ├─→ 历史数据页（分钟/小时/日/月/季/年 + 导出 Excel）
        ├─→ 数据预测页（小时预测 / 日均值预测 / 日排放量预测 + 历史基准）
        └─→ 异常记录页（超标/故障/停产/异常 + 官网标记状态，只读）
```

**核心口径链（务必记住三条）**：

| # | 规则 | 说明 |
|---|------|------|
| 1 | 服务端「流量(m3)」在**所有粒度**下都是 **m³/h**（瞬时或该时段平均流量） | 分钟数据必须 ÷60，否则排放量高估 60 倍 |
| 2 | **日排放量(t) = Σ 24 小时排放量(kg) ÷ 1000** | 官网日值就是逐小时相加 |
| 3 | **小时排放量(kg) ≈ Σ 该小时 60 分钟排放量** | 官网小时值由分钟积分而来，不是「小时均值 × 流量」 |

## 2. 时间粒度与接口能力

### 2.1 index 映射

历史接口用 `index` 区分粒度：

| index | 粒度 | 服务端是否可用 |
|---|---|---|
| -1 | 分钟 | ✅ 可用 |
| 1 | 小时 | ✅ 可用 |
| 2 | 日 | ✅ **可用，但只接受裸日期** `yyyy-MM-dd`（带 ` 00:00`/` 23:59` 后缀返回空） |
| 3 | 月 | ❌ 返回空（历史页改查小时数据客户端聚合） |

> ⚠️ **v5.83 更正**：v5.78 曾判定 `index=2`「始终返回空」（日志累计 258 次 rows=0），
> 真正根因是查询参数带了时间后缀 `2026-11-02 00:00`。日接口只接受**裸日期**，
> 带后缀即返回 0 行；小时接口恰好容忍后缀，所以从未暴露。v5.83 在
> `api_client.query_history` / `multi_account_api.query_history` 中对 `index=2`
> 自动剥离时间后缀（`bare_date()`），日数据恢复可用。
> 历史数据页（月接口仍未验证）维持小时聚合口径不变，预测页基准改回服务端日数据。

### 2.2 软件内的粒度选择

| 界面位置 | 下拉项 | 实际取数 | 排放量时间系数 |
|---|---|---|---|
| 历史数据页 | 分钟数据 | `index=-1` | **1/60** |
| 历史数据页 | 小时数据 | `index=1` | 1 |
| 历史数据页 | 日/月数据 | `index=1`（小时行，按天筛选） | 1 |
| 历史数据页 | 季度/年数据 | `index=1` → 月聚合 | — |
| 数据预测页 | 日排放量预测 | `index=2` 日数据（裸日期，v5.83 修复）+ 官网导入优先 | 1 |
| 实时监控页 | — | 实时接口当前值 | 1（展示为瞬时值） |

## 3. 流量语义：m³/h 与时间系数

### 3.1 实测证据（鼎鑫 彩涂1-3#排放口，2026-11-02，非甲烷总烃）

| 粒度 | 浓度 | 流量列 | 官网排放量 | 反推 |
|---|---|---|---|---|
| 分钟 00:00 | 1.81 mg/m³ | 119649 | 0.004 kg | 1.81×119649/60/1e6 = **0.0036** ✅ |
| 小时 00 时 | 2.06 mg/m³ | 110890 | 0.228 kg | 2.06×110890/1e6 = **0.2284** ✅ |
| 日（汇总） | 2.88 mg/m³ | 699920 | 9.570 kg | Σ24 小时 = **9.569** ✅ |

分钟那一行若不除 60 会得到 0.2166 kg —— **高估 54~60 倍**，这是 v5.80 修复的 bug。

### 3.2 时间系数规则

```
排放量(kg) = 浓度(mg/m³) × 流量(m³/h) × 小时数 ÷ 分母

粒度     小时数
分钟     1/60
小时     1
日       1        （日导出的流量已是日累计 ≈ 24×小时值）
```

代码：`param_units.calc_emission_rate(concentration, flow, code, hours=1.0)`
`hours` 默认 1.0，所有历史调用保持原行为；只有历史页分钟数据由
`main_window._query_history` 设置 `self._history_time_scale = 1/60`。

### 3.3 两套数据源的边界（v5.82 补充，勿混用）

| | 服务端 API（实时/历史/分钟） | 官网「历史数据」导出 xls |
|---|---|---|
| 流量列 | 统一 **m³/h**；分钟须 `hours=1/60` | 语义**不统一**：废气小时≈m³/h、日=日累计、废水 10 分钟桶=该桶累计体积 |
| 排放量 | 可能直接返回字段；否则 `浓度×流量÷分母` | **文件自带「排放量」列，直接采用** |
| 代码路径 | `param_units.extract_emission_mass` / `calc_emission_rate` | `web_daily_import.parse_export` |

v5.82 用 4 份冠洲导出实测：废水 10 分钟桶流量 4 m³，
`4.65 mg/L × 4 / 1000 = 0.0186 kg` 与官网「排放量(kg)」0.019 一致；
若误按 m³/h 再 ÷6 会差 6 倍。因此**导出解析一律不重算**，
只读取官网给出的排放量列（日 t→kg、小时/分钟 kg 原样）。

## 4. 排放量口径（核心）

### 4.1 公式与分母

```
排放量(kg) = 浓度(mg/m³ 或 mg/L) × 流量(m³) ÷ 分母

废气（mg/m³ × m³）：分母 = 1e6
废水（mg/L  × m³）：分母 = 1e3
```

分母按**浓度单位**决定（`param_units.get_concentration_divisor`），与排放口类型无关。

### 4.2 三层聚合关系（官网实测）

```
分钟排放量(kg) = 浓度 × 流量/60 / 1e6
       ↓ Σ 60 条
小时排放量(kg) = Σ 该小时分钟排放量          ← 官网小时列
       ↓ Σ 24 行
日排放量(t)    = Σ 24 小时排放量 / 1000      ← 官网日列（单位是吨！）
```

实测（2026-11-02，彩涂1-3#）：Σ分钟 = 0.227 ≈ 小时 0.228；Σ小时 = 9.569 ≈ 日 9.570。

### 4.3 单位陷阱

| 来源 | 排放量单位 | 处理 |
|---|---|---|
| 官网**日**导出 | **t（吨）** | ×1000 → kg |
| 官网**分钟/小时**导出 | **kg** | 原值 |
| 服务端行内排放量字段 `ex_{code}`（v5.84 起首选候选） | 小时=**kg**、日=**t（吨）** | 日吨值经 `extract_emission_mass` 的吨→kg 分支（`ratio ∈ [1e-4,1e-1] → ×1000`，v5.85 将上界由 1e-2 放宽到 1e-1）正确换算为 kg；分钟粒度 `ex_="0"`（空排放）按 `fv<=0` 跳过，回退到浓度×流量×时间公式计算 |
| 服务端其它行内排放量字段（`pf_{code}` / `pfl_{code}` / `flow_{code}` 等） | kg | 原值；量级校验自动识别 t→kg |

### 4.4 取值优先级（各模块统一）

```
① 服务端行内排放量字段（权威，含分钟积分结果）
② 小时聚合行已算好的 emis_{code}（Σ逐时）
③ 浓度 × 流量 / 分母（× 时间系数）
```

理由：官网的**小时**排放量并非简单的「小时均值 × 小时流量」——个别小时存在分钟级峰值，
例如 2026-11-02 10 时官网给 2.090 kg，而按小时均值算只有 0.745 kg。
因此凡能拿到服务端值，一律优先采用。

## 5. 浓度：实测值 / 折算值 / 标准值

官网每个浓度参数有 4 个子列：**实测值 / 折算值 / 标准值 / 排放量**。

| 概念 | 含义 | 软件处理 |
|---|---|---|
| 实测值 | 仪器直接测量值 | **排放量计算一律用实测值**（与官网一致） |
| 折算值 | 按基准氧含量折算（仅燃烧类/热电厂有值，其余为 `--`） | 仅热电厂预测使用（`use_corrected`） |
| 标准值 | 排放限值 | 预警分级依据（`get_warning_level`） |

- 热电厂判定：`ent_name` 含「热电」→ `use_corrected=True`，查询时带 `showUpload=1`。
- 折算值缺失时自动回退实测值，并在日志提示。
- 排口是否需要折算由官网排口属性决定，软件不自行换算。

## 7. 官网导出文件结构与解析规则

### 7.1 三种粒度的列结构

| 粒度 | 行数 | 子列 | 流量列位置 | 排放量单位 |
|---|---|---|---|---|
| 分钟 | ≈1440/天 | 实测/折算/标准/排放量/状态 | 19 | kg |
| 小时 | 24/天 | 实测/折算/标准/排放量/来源/状态 | 22 | kg |
| 日 | 1/天 | 实测/折算/标准/排放量 | 22 | **t** |

> ⚠️ 导出文件名中的「分钟/小时/日」与实际粒度可能不一致，判断依据是**监测时间列是否带 `:MM`**。

### 7.2 解析规则（`src/web_daily_import.py`）

1. 第 2 行 = 参数名（含单位，合并单元格，需向前填充）；第 3 行 = 子列名。
2. 只取子列含「排放量」的列；按子列单位换算：`(t)` → ×1000；`(kg)` → 原值。
3. 跳过汇总行（监测时间为「平均值/最大值/最小值/累计值」）。
4. **同一日期多行按小时累加**为日排放量（分钟粒度导出即为 Σ 小时口径）。
5. 参数名剥离任意括号内容再入库。v5.82 修正：旧正则漏了废水单位 `mg/L`，
   导致「化学需氧量(mg/L)」原样成 key，与系统内部名匹配不上、废水数据全部失效。
6. 按「企业 | 排口 | 参数」分组持久化到 `data/web_daily_import.json`，重复导入增量更新。
7. v5.82：改用纯 `xlrd`(.xls) / `openpyxl`(.xlsx) 读取，去掉 `pandas` 依赖
   （该依赖未在 PyInstaller `hiddenimports` 中，打包版存在缺依赖风险）。

### 7.3 导入后的用途（v5.78+）

预测页「📄 导入官网日数据」→ 该排口该参数 ≥3 天时，**直接以导入序列的日均作为历史基准**（标签「官网导入日均(N天)」），不再套用「上一天 + 前 10 工作日」组合，保证与网页逐日一致。

### 7.4 部分天不参与基准（v5.82 新增）

官网导出的小时/分钟数据常常只覆盖半天，例如：

| 导出 | 实际覆盖 | 累加排放量 | 是否计入日均 |
|---|---|---|---|
| VOCs总排口 11-12 小时 | 00–06，7 个不同小时 | 0.611 kg | ❌ 部分天 |
| 总排口 11-11 分钟 | 07:00–23:50，17 个不同小时（102 桶） | 2.359 kg | ❌ 部分天 |
| 总排口 11-12 小时 | 00–06，7 个不同小时 | 0.860 kg | ❌ 部分天 |
| VOCs总排口 11-01~11-11 日 | 11 个完整日 | 各日 t→kg | ✅ 完整 |

判定：日粒度导出视为完整；小时/分钟粒度按**不同小时数**统计覆盖，
`< 18` 小时记为 `partial_days`（与 worker 的「有效小时 <18 判缺数」一致），
从 `values_kg` 与 `get_series()` 基准序列中排除，数值仍保留供查看。
导入弹窗提示忽略数量；若本次只导出了部分天，明确提示「基准保持不变」。
若把 0.611 / 2.359 这类半天值当作整天混入日均，会显著拉低基准——
这正是「软件基准与网页导出不一致」的主要成因之一。

## 8. 日排放量预测的取数与基准

### 8.1 取数链路

```
① 官网导入序列（若已导入该排口/参数，≥3 天）   ← 优先级最高，直接作为基准
② index=2 日数据（v5.83 修复：裸日期可用，与官网日口径一致；探测返回空则降级小时聚合）
③ index=1 小时数据 → 客户端按日聚合（emis_{code} = Σ逐时，兜底口径）
```

### 8.2 小时聚合规则（`_aggregate_hour_rows_to_daily`）

| 产出字段 | 含义 |
|---|---|
| `val_{code}` | 该日各小时**算术平均**（浓度类） |
| `flowsum_{code}` | 该日**Σ 小时流量**（m³/日，排放量封顶与浓度反推必须用它） |
| `emis_{code}` | 该日**Σ 逐时排放量**（kg/日） |
| `hours_{code}` | 该日有效小时数（完整性校验用） |
| `emis_src_{code}` | `server`（用了服务端排放量）/ `calc`（自行换算） |

### 8.3 历史基准（基线）口径

**定义：基准 = 参与时段的日排放量算术平均值**（单位 kg/天）。

| 基线模式 | 取值 |
|---|---|
| `custom` + 指定时段 | 时段内**完整序列**的算术平均（含真实峰值天） |
| `custom`（其它组合） | 上一天 与 前 N 工作日均值 的组合平均 |
| `prev_day` | 上一天实测值 |
| `last_10_workdays` | 前 10 个工作日均值 |
| `auto`（默认） | 上一天 + 前 10 工作日 的组合平均 |
| `all_history` | 全部历史加权移动平均（半衰期 5 天） |

**重要区别**：
- 「历史基线」列显示的是**未叠加自学习偏差**的纯日均（`baseline`），可与网页直接核对；
- D+1…D+N 预测值来自 `predicted = baseline × 自学习偏差`，属另一口径。

### 8.4 数据质量处理

| 情形 | 处理 | 版本 |
|---|---|---|
| 整日无数据 | 该日剔除，不计入平均 | v5.72 |
| 排放量 = 0 且有效小时 < 12 | 剔除（缺数被当成 0） | v5.77 |
| 有效小时 < 18 且排放量 < 中位数×30% | 判定缺数天剔除 | v5.77 |
| 当天数据未过完 | 剔除今天 | v5.63 |
| IQR 异常值过滤 | **仅用于趋势/预测**，不影响自定义时段的基准 | v5.77 |

## 9. 异常识别与官网数据标记

### 9.1 状态分类

服务端每个参数行带 `state_{code}` / `status_{code}`，**这两个字段就是官网「日常工作 → 数据标记」的结果**（官网导出里的「排放量/状态/来源」列同源）。

| 标记 | 分类 | 说明 |
|---|---|---|
| `0` / 空 / `N` | 正常 | 无标记 |
| `1`、`4`~`9` | 超标 | 数值超标准值 |
| `2` / `F` | 故障 | 仪器故障 |
| `3` / `S` | 停产 | 停产 |
| 其它非空 | 异常 | 未知标记（记录为「异常」） |

代码：`data_processor.classify_data_state`。

### 9.2 标记状态在软件中**只读**

异常记录页的「官网标记」列直接由 `state`/`status` 推导：

- 有非空标记 → `✅ 已标记`（悬停显示标记原文，如 `2 / 非甲烷总烃故障`）
- 无标记 → `⏳ 待标记`

软件**不提供任何本地标记功能**（v5.75 起移除「标记已处理/未处理」按钮与右键菜单），
避免软件内标记与环保平台不一致造成「环保标记错误」。请到官网「日常工作 → 数据标记」处理，
下次扫描软件会自动同步。

## 10. 数据缺失判定规则

异常记录中的「数据缺失」指：**该参数在本行没有有效数值**，但同周期其它参数有值。

| 规则 | 说明 |
|---|---|
| 无效值判定 | 空 / `--` / 非数值 / ≤ -9998（哨兵值） |
| 判定前提 | 同一行的其它参数有有效值 |
| **窗口内从未报送的 code 不判缺失** | 总排口常同时配置 废水流量(492)/累计流量(495)/流量(210)，但只报送其中一部分；未报送的 code 整段窗口无值，不应每小时误报（v5.72 修复） |
| 突然缺数仍报 | 该参数窗口内曾有值、某天突然缺失 → 正常记为异常 |
| 一次性清理 | 升级时清除旧逻辑产生的「数据缺失」误报记录（带标记，保证只清一次） |

## 11. 与其他模块口径一致的要点

| 模块 | 要点 |
|---|---|
| 实时监控 | 排放量 = 实测浓度 × 当前流量（瞬时值，非时段累计）；折算值仅热电厂显示 |
| 历史数据 | 排放量优先取 `emis_`/服务端字段，其次公式；分钟粒度 ÷60 |
| 历史导出 | 与界面同口径，导出列名带单位（如 `非甲烷总烃排放量(kg)`） |
| 预测（小时） | 基于当前小时内的分钟数据内推当日均值；**不做**跨日外推 |
| 预测（日排放量） | 见第 8 章；历史基线为纯日均，预测值含自学习校准 |
| 预警 | 用排放量 ÷ 日流量反推浓度后按标准值分级；缺流量则不做反推 |
| 排放量封顶 | 浓度限值 × 参考日流量 ÷ 分母 × 1.5，防止超标后无限外推 |

## 12. 常见差异排查表

| 现象 | 原因 | 处理 |
|---|---|---|
| 分钟数据排放量比官网大约 60 倍 | 未把 m³/h 折算成分钟风量 | v5.80 已修（×1/60） |
| 日排放量比官网低，且某天明显偏低 | 该天小时数据缺数/缺峰值 | v5.77 已剔除缺数天；日志 `小时有效小时仅 N` |
| 基准比官网低（少一天） | 该天被判缺数剔除 | 看 tooltip「参与天数」与日志，必要时用官网导入 |
| 基准比官网高/低一个系数（1000 倍） | 官网日导出单位是 t | 导入时已自动 ×1000；手工核对请注意 |
| 基准与网页差一个百分比 | 官网用折算浓度、软件用实测浓度 | 统一用实测值；热电厂须确认 `use_corrected` |
| 某小时官网值与「浓度×流量」差很大 | 服务端按分钟积分/异常处理 | 软件优先采用服务端值 |
| 预测基准比官网日导出高出一个系数 | 官网日「排放量」是**分钟级积分**，服务端日接口只有「日均浓度×日累计流量」；峰值天（如 11-02 达 1.67 倍）会明显高估 | 需与官网逐日完全一致时，用「📄 导入官网日数据」 |
| 日接口拉不到数据（返回空） | 查询参数带了时间后缀 ` 00:00`/` 23:59` | v5.83 已修：index=2 自动剥离后缀传裸日期 |
| 日排放量比官网低 ~40%（某天明显偏低） | 日行 `ex_{code}` 是**吨**单位，旧版候选不含它，被量纲守卫 `[0.1,10]` 拒绝后回退「日均浓度×日累计流量」，丢分钟峰值 | v5.84 已修：`ex_{code}` 提为首选候选 + 吨→kg 分支；分钟 `ex_="0"` 跳过回退公式 |
| 某天（如峰值天）排放量被低估近千倍（5.97 kg 显示成 0.006 kg） | 该天**日均浓度 `val_{code}` 失真**压低了 kg 估算值，使吨判定比值 `ratio` 越过 1e-2 上界，被误判为「已是 kg」 | v5.85 已修：吨判定窗口上界放宽到 1e-1；合法 kg 比值约 1 与此天然分离，不会误乘 |
| 异常记录里出现「废水流量 数据缺失」 | 旧版本误报（未报送参数） | v5.72 已修 + 一次性清理 |
| 日预测无结果 | 该排口无流量参数，无法换算排放量 | 提示语已给出原因 |
