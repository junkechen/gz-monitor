| 项目 | 说明 |
|------|------|

## 二、服务端 HTTP 接口（远程服务器）

### 2.1 认证流程（4 步）

| 步骤 | 方法/路径 | 说明 |
|------|-----------|------|
| 1 | `GET /` | 获取 `ASP.NET_SessionId` Cookie |
| 2 | `GET /ajax/SliderValidImg.ashx?method=GetSliderImg` | 获取滑块验证码 |
| 3 | `GET /ajax/SliderValidImg.ashx?method=CheckSliderImg&p={enc_trail}` | 遍历 `trail=40~200`（步长 3），AES 加密后提交，`Code=0` 为验证成功 |
| 4 | `POST /Ajax/Login.ashx?Method=CheckLogin` | Body：`p1={enc_user}&p2={enc_pass}&p3={enc_trail2}`，Referer 为 `/Login/index.aspx` |

**AES 加密参数表**

| 参数 | 值 |
|------|-----|
| 算法 | AES-256-CBC |
| KEY | `1234567890abcdefghijklmnopqrstuv`（32 字节） |
| IV | `1234567890abcdef`（16 字节） |
| 输出 | Hex 字符串（`ct.hex()`） |
| 填充 | PKCS7（`Crypto.Util.Padding.pad`） |

**登录返回码**

| 返回值 | 含义 |
|--------|------|
| `ok` | 登录成功 |
| `errorvalid` | 验证码错误 |
| `errorpassword` | 密码错误 |
| `usernotexist` | 用户不存在 |

### 2.2 实时数据接口

**① 获取企业排口列表**

```
POST /Web6/ajax/MonitorControl/Enterprise/EnterPriseRealTimeData.ashx?Method=GetEnterPriseTotalSubs&_={ts}
Content-Type: application/x-www-form-urlencoded; charset=UTF-8
Referer: {BASE_URL}/Web6/MonitorControl/Enterprise/EnterPriseRealTimeData.aspx
Body: (空)
```

返回 JSON 数组，元素字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `SubId` | int | 排口 ID |
| `SubName` | string | 排口名称 |
| `SubType` | int | 排口类型（51=废水，64=VOCs） |
| `EnterPriseId` | int | 企业 ID |
| `EnterPriseName` | string | 企业名称 |

**② 获取实时监测数据**

```
POST /Web6/ajax/MonitorControl/Enterprise/EnterPriseRealTimeData.ashx?Method=GetEnterpriseRealtimeData&_={ts}
Content-Type: application/x-www-form-urlencoded; charset=UTF-8
Referer: {BASE_URL}/Web6/MonitorControl/Enterprise/EnterPriseRealTimeData.aspx
Body: (空)
```

返回结构：`{"total": int, "rows": [...], "sRows": [...]}`（`sRows` 为同值检测结果）。`rows` 元素字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | int | 监测项 ID |
| `name` | string | 监测项名称 |
| `code` | string | 监测项代码 |
| `value` | string | 实测值 |
| `standard` | string | 标准值/告警阈值 |
| `iscvt` | string | 是否折算：`"0"`=否，`"1"`=是 |
| `cvt` | string | 折算值（iscvt="1" 时有值） |
| `time` | string | 数据时间 |
| `status` | string | 状态：`"1"`=正常 |

> 客户端调用前先 `GET EnterPriseRealTimeData.aspx?_={ts}` 触发服务端刷新（Accept 需临时覆盖为 text/html），随后等待约 0.3~1.5s 再 POST；若返回 HTML 或含 "Login"/302 视为 Session 过期。

### 2.3 历史数据接口

```
POST /ajax/WasteGas/QueryAnalysis/HistoryReportQUIDYN/HistoryReport.ashx
Content-Type: application/x-www-form-urlencoded
Referer: {BASE_URL}/Web6/MonitorControl/Enterprise/HistoryData.aspx
```

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `Method` | string | ✓ | 固定 `QueryHistoryReport` |
| `subid` | int | ✓ | 排口 ID |
| `subtype` | string | ✓ | `51`=废水，`64`=VOCs |
| `index` | int | ✓ | 时间类型：`-1`=分钟，`1`=小时，`2`=日，`3`=月 |
| `start`/`end` | string | ✓ | `YYYY-MM-DD HH:MM`，需 URL 编码 |
| `codes` | string | ✓ | 监测项目代码，逗号分隔，如 `"302,311,316"`，需 URL 编码 |
| `sort` | int | | 固定 `1` |
| `showValidate` | int | | 固定 `1` |
| `showUpload` | int | | `0`=实测数据，`1`=折算数据 |
| `selectcity` | int | | 固定 `0` |
| `page`/`rows` | int | | 页码默认 1；每页默认 1000 |

**返回结构**：`{"total": int, "rows": [...], "pf_flow": ""}`。rows 元素含 `time`、`val_{code}`（实测值）、`cvt_{code}`（折算值，仅 showUpload=1 时返回）、`standard_{code}`（标准值）。

**index 时间类型与 v5.18 聚合变更**

| 值 | 含义 | 服务端支持 | 说明 |
|----|------|-----------|------|
| `-1` | 分钟 | ✅ | 用于实时/预测取数 |
| `1` | 小时 | ✅ | 默认取数类型 |
| `2` | 日 | ❌ | 服务端返回空，客户端改用 index=1 后按 `yyyy-MM-dd` 分组取均值 |
| `3` | 月 | ❌ | 同上，按 `yyyy-MM` 分组取均值 |

**showUpload 说明**：`0`=实测数据（普通企业）；`1`=折算数据（企业名含"热电"，如冠县恒润热电有限公司）。

### 2.7 注意事项

1. 所有请求参数（用户名/密码/滑块偏移量）需 AES-256-CBC 加密后转 Hex。
2. 登录后须用同一 Session（ASP.NET_SessionId）发起后续请求；Session 过期时实时接口返回 HTML/302，客户端自动标记 `logged_in=False` 并重登。
3. 部分接口校验 Referer，须按上表填写。
4. 历史数据可能超 1000 条，需循环 `page=1,2,3...` 分页获取。
5. 仅热电厂使用 `showUpload=1`，其余用 `0`。
6. `index>=2` 查询前需先 GET `HistoryData.aspx` 初始化 Session，否则返回空。

### 3.3 后台 Worker 契约（QThread，v5.36–v5.38）

| Worker | 信号 | 输入参数 |
|--------|------|----------|
| `PredictionWorker(QThread)` | `prediction_done = pyqtSignal(list)` | `grouped_data`、`multi_client`、`prediction_horizon`、`prediction_params`、`pred_type`、`thresholds` 及各缓存 dict |
| `HistoryFetchWorker(QThread)` | `history_result = pyqtSignal(dict)`、`fetch_finished = pyqtSignal()` | `multi_client`、`sub_tasks`、`history_cache`（共享 dict）、`ttl` |
| `RefreshDataWorker(QThread)`（v5.38） | `data_ready = pyqtSignal(object)`（传 `(grouped_data, grouped_data_for_warning)` 元组）、`fetch_failed = pyqtSignal(str)` | 刷新周期触发的实时取数 |
| `LoginWorker(QThread)`（v5.38，main.py） | `progress = pyqtSignal(str)`、`login_finished = pyqtSignal(dict)` | 登录进度与结果回传 |

**HistoryFetchWorker 任务/结果结构**

- `sub_tasks` 元素：`{subid, subtype_code, codes, params:[(code,name,axis)], start, end, index, use_corrected, subname, ent_name}`——按 sub 聚合，一次网络请求取全量 codes，本地按 `val_{code}` 拆分多参数 series。
- `history_result` payload：`{subid, subname, ent_name, subtype_code, window, series:[{param_name, code, axis, times, values}]}`。
- 内置 `_get_cached(key, ttl, fetch_fn, *a, **k)` 复刻 PredictionWorker 缓存模式；`_build_series` 对非法值置 `None`。

**QThread 生命周期铁律（v5.36–v5.38）**

1. Worker 引用必须保留在实例 dict/list 中（如 `self._hist_worker`），防止运行时被 GC 析构导致崩溃。
2. `finished` 信号回调中先移除引用，再 `deleteLater()`。
3. `closeEvent` 统一 `quit()` + `wait(3000)`，避免线程残留。
4. 所有 pyqtSignal 自动桥接回主线程更新 Qt；网络 I/O 与同步重绘不得出现在主线程。

### 3.5 ChartWidget.plot_series（`src/chart_widget.py`）

```python
plot_series(times, series_list, title, right_series_list=None,
            right_ylabel="", normalize=False, selected_names=None)
```

- `series_list` / `right_series_list` 元素：`{name, data, times?}`，`name` 即图例名（彩色 QCheckBox）。
- `normalize=True`：所有 series 各自 min-max 映射到 [0,1]，**强制单轴**（忽略右轴/twinx）。
- 否则：左轴画 `series_list`；`right_series_list` 非空时 `ax.twinx()` 画右轴并设 `right_ylabel`。
- 图例显隐 `_toggle_line(name, state)` 按 name 命中 `_lines`/`_right_lines`；`_auto_scale` 对两轴可见线分别缩放；归一化时 ylim 固定 0–1。
- 向后兼容旧调用（右轴/归一化默认关闭）；figure `dpi=FIG_DPI(80)`。

| 接口 | 签名 | 说明 |

| `check_and_alert` | `(data, thresholds)` | 三类预警：超标（上下限）、同值（`SAME_VALUE_THRESHOLDS` 分钟窗口）、急剧变化（`RAPID_CHANGE_THRESHOLDS` 百分比+冷却 5 次）；仅处理 `IMPORTANT_PARAMS`（化学需氧量/氨氮/非甲烷总烃/二氧化硫/氮氧化物/颗粒物/pH值） |
| `check_and_alert_predictions` | `(prediction_results, thresholds, confidence_threshold=None)` | 预测预警；含置信度门槛（默认 0.15）、防抖（连续 2 次）、迟滞（±3%）、低置信度(<0.30)最高橙色 |
| `set_sound_enabled` / `set_sound_type` / `set_warning_callback` / `start_alert` / `stop_alert` | 声音与回调 | `beep1/beep2/beep3` 三种音型，按等级区分频率/节奏，`winsound.Beep` 后台线程播放 |
| 预警等级 | `正常/黄色预警/橙色预警/红色预警` | `_merge_and_notify` 合并实时+预测取最高级并回调 `warning_callback(all_details, is_warning, max_level)` |
| `get_warning_history` / `clear_history` / `get_warning_count_today` | 历史管理 | 历史写入 `data/warning_history.json`（最多 1000 条） |
| 干预管理 | `record_intervention` / `verify_intervention` / `get_intervention_accuracy` | 记录/验证干预事件，统计预测准确率（`data/intervention_history.json`） |

## 四、数据缓存与存储约定

| 缓存 | Key | TTL | 值 |
|------|-----|-----|-----|
| 历史数据缓存 | `(subid, subtype_code, codes, start, end, index, use_corrected)` | `HISTORY_TTL=86400`（24h） | `(timestamp, rows)` |
| API 数据缓存（PredictionWorker） | 内部 `_get_cached(key, ttl, fetch_fn)` 模式 | 60s | 实时/预测所需数据 |

- 历史缓存为主线程持有的共享 dict，Worker 跨线程读写（GIL 下读多写少安全）；主线程先预检命中者即时成 series，未命中者交给 Worker。
- 历史取数固定近 24h：`end=now`、`start=now-24h`，格式 `%Y-%m-%d %H:%M`，`index=HISTORY_INDEX(1)`。
- **series 命名规则**：`label = f"{param}@{subname}"`；多企业时升级为 `f"{param}@{ent_name}-{subname}"` 以消歧。

## 五、错误码与异常处理约定

### 5.1 登录返回码

| 码/文本 | 含义 | 客户端处理 |
|---------|------|-----------|
| `ok` | 成功 | `logged_in=True` |
| `errorvalid` | 验证码错误 | 提示重试 |
| `errorpassword` | 密码错误 | 提示 |
| `usernotexist` | 用户不存在 | 提示 |
| 其他文本 | 登录失败 | 原样透传；登录循环最多重试 3 次 |

### 5.2 数据接口返回格式

- 统一结构：`{total, rows, error}`（实时接口另含 `sRows`）。
- **空数据兜底**：`rows==[]` 视为正常空结果，界面显示"暂无数据"占位（`render_empty`），不视为故障。
- 防御处理：服务端可能返回 `rows: null`，客户端统一 `result.get('rows') or []` 兜底；响应非 dict 时构造 `{"total":0,"rows":[],"pf_flow":""}`。

### 5.3 客户端异常保护

- `_do_refresh_data` 全局 `try/except`，任何异常不阻塞 UI 主循环。
- 各 Worker 内部 `try/except`（如 `_fetch_one`），单 sub 失败仅告警跳过，不影响其余任务，`fetch_finished` 仍会发出。
- 网络层 `_request_with_retry`：连接错误/超时指数退避重试 3 次；HTTP 4xx 不重试。
- Session 失效检测：实时接口返回 HTML/302/含 "Login" → `logged_in=False` → 触发重登。
- 预警状态字典设容量上限（500）并裁剪最老条目，防止长期运行内存膨胀。
